# 衣橱管家 · wardrobe-manager

本地优先的 AI 数字衣橱。衣物、搭配、OOTD 等业务数据默认保存在本机 Hive，不上传业务服务器。
AI 功能通过用户自行配置的 OpenAI 兼容网关调用，相关图片会发送至所选模型服务商。

## 功能

**衣橱基础**
- 单品拍照录入、标签、分类、材质、适穿温度
- 搭配方案保存、OOTD 记录、利用率与单次穿着成本统计
- 衣橱体检：健康度评分、配色分布、最划算 / 该断舍离榜
- 六套风格灵感（Clean Fit / Y2K / City Walk …），按风格 + 温度重排整套

**MVP：AI 全身照自动拆分**
- 上传全身穿搭照，视觉模型识别上衣、外套、下装、鞋、配饰，返回归一化 bbox
- 按 bbox 裁剪 + 可插拔抠图（本地边缘泛洪），成功存透明 PNG，失败降级为矩形裁片并标记，可重试
- 拆分结果人工修正：改分类 / 细分 / 颜色 / 风格 / 季节、拖拽调 bbox、删误识别、合并重复、单件重裁
- 批量上传 + 任务队列：串行处理，单张失败不影响其他，失败可重试
- 重复单品检测：感知哈希 + 分类颜色兜底，只在确认页提示，不阻止入库
- 本地导入导出：JSON + 图片打包成 zip，恢复时图片缺失只计数不崩溃
- 搜索、筛选（分类 / 材质 / 状态 / 颜色 / 季节 / 场合 / 标签）、六种排序
- 网关连通性测试，脏 JSON 自动提取 `{...}` 再解析，失败保留原始响应
- 离线降级：未配网关仍可手动录入，失败保留原图与任务

**迭代 1：穿着与日常**
- 首页一键打卡（「就穿这套」），连续打卡天数与积分
- 场合约束推荐：通勤 / 约会 / 运动 / 面试 / 旅行，切换即重排整套
- 洗护中心：送洗 / 干洗、记录洗了几天、超 3 天标红提醒、一键收回衣柜
- 穿搭分享卡：海报 / 网格 / 极简三种模板，导出 PNG 走系统分享
- 闲置率与成本报表：90 天未穿占比、平均闲置天数、从未穿过件数、按分类投入
- 图片管家：占用统计、孤儿图清理（24h 内新图保护）、批量压缩
- 隐私增强：上传前旋正 + 限长边 1280 + 重编码，彻底移除 EXIF（GPS / 机型 / 拍摄时间）

**迭代 2：试穿、风格与扩展（1.5.0）**
- 2D 虚拟试穿：独立页面 + `TryOnTask` 表 + 独立编辑网关；人像照片只存本机，结果图也落本地；
  网关没配 / 模型不支持 / 生成失败都退回「搭配预览」，不阻塞使用
- 风格画像：先出本地统计结论（秒出、不联网），再按需调文本网关做 AI 深度解读；
  输出风格构成、结构缺口、配色诊断、可入手清单（可一键进愿望清单）、先别买什么
- 愿望清单：种草 → 7 天冷静期 → 已购入，购入后自动转成衣橱单品
- 穿搭日历：月历视图 + 连续记录天数 + 当天搭配明细
- 多衣橱：按物理位置分空间（家里 / 宿舍 / 老家…），切换只改浏览范围，
  删除空间时衣物退回主衣橱，长按单品可移动到别的空间
- 3D 衣橱：真实单品图环形透视陈列，可拖拽旋转、近大远小、点击看细节

## 隐私说明

- 衣橱数据、搭配记录、OOTD 默认本地存储，不上传业务服务器
- API Key 仅保存在本机安全存储（Android Keystore / iOS Keychain），**不写入 Hive**
- 使用 AI 拆分、识图、试穿时，相关图片会发送到用户配置的模型网关
- 本应用不提供默认云端账户体系，不做云同步
- 导出备份前会提示数据隐私风险；备份文件含照片，属于个人数据
- 试穿结果为 AI 搭配参考图，不保证与实物一致；不使用人脸替换，只做服装替换
- 风格分析的 AI 模式只发送**统计摘要**（品类 / 颜色计数、利用率等），不发送照片、品牌与价格明细
- 愿望清单与穿搭日历纯本地，不联网

## AI 能力说明

拆分采用「视觉模型识别 + 本地裁剪 / 抠图」，而不是让模型直接吐透明图：

1. 视觉模型只负责**识别品类与包围盒**，返回严格 JSON；
2. 裁剪和抠图由 `CutoutService` 在本地完成（纯 Dart，不联网）；
3. 抠不干净时降级为矩形裁片，照常入库，页面可单件重试；
4. 后续可替换成 rembg / SAM / 分割 API，页面与 Hive 都不用改。

视觉模型必须支持图片输入；JSON 输出不是硬要求（不勾选时会做容错解析）。

## 快速开始

```bash
git clone https://github.com/baitb6/wardrobe-manager.git
cd wardrobe-manager
flutter pub get
flutter run
```

首次打开衣橱是空的，点「先看示例」可载入 12 件示例数据。

### 配置 AI 网关

「我的 → AI 网关」分三组配置：视觉模型、文本模型、图像编辑模型（迭代 1）。

| 项 | 说明 |
| --- | --- |
| 网关地址 | OpenAI 兼容，通常以 `/v1` 结尾 |
| 模型 ID | 视觉：`gpt-4o` / `glm-4v` / `qwen-vl-max`；文本：`gpt-4o-mini` / `deepseek-chat` |
| API Key | 存系统安全存储，不落库 |
| 超时 | 默认 90 秒，大图可调到 120 |
| 支持图片输入 | 视觉模型必须打开 |
| 支持 JSON 输出 | 打开后强制 `response_format`；不确定就关，程序会容错解析 |

页面提供常用网关的一键填充，填完点「测试连通性」确认再保存。

## 打包

```bash
flutter build apk --release                  # 通用包
flutter build apk --release --split-per-abi  # 分 ABI，arm64 更小
flutter build web --release
```

仓库已带 `android/key.properties` 与自签 keystore（口令 `wardrobe2026`），可直接出包。
正式分发请替换成自己的密钥，并保证后续升级使用同一份。

- 包名 `com.baitb6.wardrobe`，`minSdk 24`、`targetSdk 36`
- 图标为自适应图标（含 Android 13 单色层），启动背景为奶油色
- `--split-per-abi` 的包 versionCode 带 ABI 偏移（arm64 = 2013，通用包 = 13），两者不要混装

## 已知限制

- 抠图是本地颜色泛洪，只对浅色 / 纯色背景效果好；复杂背景会主动降级为矩形裁片
- 拆分准确度取决于模型：一次超过 6 件或大量遮挡时容易漏识别，可在确认页手动删改
- 网页版没有文件系统，AI 拆分、图片管家、备份与分享卡导出仅在 App 内可用
- 手动录入的照片由 image_picker 先压到 800px / q70，本身已不含原始 EXIF；EXIF 清理主要作用在全身照上传链路
- 图片管家的孤儿判定只覆盖 Hive 引用；导入确认页里尚未入库的裁片靠「24 小时内不清理」保护
- 备份恢复到同 ID 的衣物会覆盖，不会删除现有数据
- 语音输入未接入，界面不放入口
- 3D 衣橱是「真实单品图的环形透视陈列」，不是单件白模网格；单件 3D 模型需要美术资源，未接入
- 虚拟试穿依赖第三方图像编辑模型，效果受模型能力限制；不上传人脸做换脸，只做服装替换
- 多衣橱切换只影响衣橱列表浏览范围，推荐与统计仍按全部单品计算（避免换空间后推荐为空）
- 白底商品图由图像编辑模型生成，成品质量取决于网关与模型；入库前需人工确认，不是本地抠图
