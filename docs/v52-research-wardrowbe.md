# v5.2 候选需求（wardrowbe 竞品调研）

日期：2026-11-25 03:40 · 来源：用户点名参考 GitHub 火项目 wardrowbe（Anyesh/wardrowbe，866★，本周仍在更新，MIT，Next.js+FastAPI+Postgres+Redis，自托管 AI 衣橱）

## 对方做而咱们没有的（按价值排序）

1. **每日穿搭推送**（定时通知，ntfy/Mattermost/邮件/推送，不用打开 App 就收到当日推荐）
   - 落点：App 端本地通知（flutter_local_notifications）+ 服务端定时任务生成推荐文案
   - 价值：唤醒留存的最强功能，衣橱类 App 的高频痛点
2. **穿着追踪反馈闭环**（wear tracking：历史带评分、穿搭反馈回流推荐）
   - 落点：outfit 历史已存，加「这条推荐准不准」评分（👍👎），反馈写入评分权重
   - 价值：推荐越用越准，是 AI 衣橱护城河
3. **衣柜分析视图**（analytics：常穿/从不穿/颜色分布/品类占比）
   - 落点：统计页扩展，纯本地计算，零成本
   - 价值：对用户有「断舍离」实用价值
4. **家庭模式**（多成员衣橱）
   - 落点：数据模型加 owner 维度 + 管理后台成员管理，改动大
   - 价值：家庭用户增量
5. **AI 能力分级开关**（vision/text 逐能力独立开关 + 超时/重试/并发/冷却参数化）
   - 落点：管理后台 settings 拆 ai_vision_enabled / ai_text_enabled
   - 价值：精细控制成本，运维友好
6. **国际化（8 语言）**：暂不做（单语用户群）

## 对方做得不如咱们的（保持优势）

- **移动端**：wardrowbe Google Play 还没上架、iOS 独占；咱们 Flutter 双端 ✓
- **生图能力**：对方只有 vision 打标+文本推荐，没有试穿/白底/数字人生图 ✓
- **直连隐私**：对方全走自托管服务器；咱们 v1.9 App 直连厂商（图片不过服务器）✓
- **Key 安全**：同类 tandpfun/wardrobe（2234★）把 key 打进客户端 bundle 裸奔；咱们凭证下发+24h TTL+五类作用域 ✓
- **多模型路由**：对方单一 base_url 双模型名；咱们 8 模型多网关可切换可降级 ✓
